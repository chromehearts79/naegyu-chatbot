# 내규챗봇 AI 위험 수준 자체평가 및 운영관리 방안

> 「인공지능전환관리세칙」 제24조·제25조에 따른 위험 수준 자체평가와 고영향 AI 해당 여부를 확인하고, 제29조부터 제32조까지의 관리 방안을 정하고자 함

## 시스템 개요

### 구성
- 문답 카드 1,010장(내규 71개 전체): 생성형 AI가 내규 원문을 근거로 미리 작성
- 직원용 화면: 단일 HTML 파일, 규칙 기반 글자 검색으로 카드를 찾아 보여 줌(실행 중 AI 모델 없음)
- 근거 표시: 모든 답에 인용 조문 원문 연결, 인용 문구 6,381개 원문 일치 확인

### 데이터 흐름
- 입력: 내규 원본(한글 파일) → 조문 단위 변환 → 카드 작성·검증 → 화면 파일 묶기
- 직원 질문: 브라우저 안에서만 처리하며 서버·외부로 보내지 않음(외부 접속 차단 설정, 기록·저장 없음)

## 위험 수준 자체평가(제24조제1항)

### 별표 제1호 대조
| 위험 수준 | 판단 | 근거 |
| --- | --- | --- |
| 수용할 수 없는 위험 | 해당 없음 | 이용자 조작·평점 부여 기능 없음 |
| 고위험(고영향) | 해당 없음 | 채용·인사평가·대출 심사 등 개인에 대한 결정에 쓰지 않음 |
| 제한적 위험 | **해당** | 이용자와 상호작용하는 챗봇 형태, 답변을 생성형 AI가 작성 |
| 최소한의 위험 | 해당 없음 | 생성형 AI 작성물을 제공하므로 제한적 위험으로 분류 |

### 제한적 위험 통제 원칙 이행
- AI 이용 사실 고지·표시: 화면 상단 고지, 답마다 'AI 작성 · 담당부서 검수 전' 표시
- 결과물 정확성 검증
  - 1단계 프로그램 검사: 인용 조·항·호 존재, 인용 문구·숫자 원문 일치
  - 2단계 AI 재확인: 다른 AI 모델이 값을 숨긴 채 다시 찾아 비교(6,381개 항목), 위임전결 표 227칸 프로그램 대조
  - 3단계 담당부서 검수: 분류별 검수표로 진행 예정, 완료한 답에 '검수 완료·날짜·부서' 표시

## 고영향 AI 해당 여부 확인(제25조제1항)

### 확인 결과
- AI 시스템 해당 여부: 카드 작성 단계에서 생성형 AI 사용, 직원용 화면은 AI 시스템 아님(규칙 기반 검색)
- 고영향 AI 해당 여부: **해당 없음**
  - 생명·신체 안전, 기본권에 중대한 영향을 주는 영역(별표 제1호 예시)에 쓰지 않음
  - 답변은 안내용이며 인사·징계·급여 결정은 담당부서가 원문에 따라 처리

## 정보보안 및 개인정보 보호(제29조)

### 외부 AI 입력 정보
- 카드 작성에 쓴 자료: 공개 대상 내규 원문(「내규관리세칙」 제20조, ALIO 공시)과 국가법령정보 공개 법령
- 개인정보·신용정보·비공개 정보는 입력하지 않음
  - 작업 폴더에 있던 채용업무관리세칙 개정 시행문(직원 성명·메일 포함)은 카드 작성에 쓰지 않았음. 업무용 저장소로 옮길 때 제외 필요
- 확인 필요: ALIO 공시본이 이전 판인 위임전결세칙(2026. 7. 13.판)을 외부 AI에 입력한 것이 공개 범위 안인지 정보보안담당관 확인

### 배포본 보안
- 외부 주소 접속 차단(콘텐츠 보안 정책), 질문 기록·저장 없음, 로그인 없음
- 확인 필요: 시범본을 외부 서비스(claude.ai)에 비공개로 게시해 둔 것을 계속 둘지 정보보안지침에 따라 결정
- 배포 파일 위변조 방지: 배포본 해시값을 게시판에 함께 공개하는 방안 검토

## 투명성과 이용자 보호(제30조·제31조)

### 고지와 설명
- 모든 답에 근거 조문 원문을 열어 볼 수 있어 결과의 근거 설명이 가능함(제31조제2항)
- 내규에 직접 규정이 없을 수 있는 질문에는 바로 답하지 않고 담당부서 확인 안내

### 오류 신고·이의제기 절차(제31조제1항)
- 창구: 답마다 '오류 신고' 버튼 → 신고 내용 작성 → 운영부서 메일(또는 메신저)로 전달
  - 운영부서·메일 주소는 지정 후 설정 파일(knowledge/site.json)에 입력
- 처리: 접수 후 7일 이내 소관부서 확인 → 카드 수정·검증 → 다음 판에 반영, 신고자에게 회신
- 기록: 신고·처리 내역을 분기별로 정리해 주관부서에 보고

## 모니터링과 개정 대응(제32조)

### 정기 점검
| 지표 | 주기 | 기준 |
| --- | --- | --- |
| 시험 질문 처리율 | 분기 | 90% 이상 |
| 바로 답 중 틀린 답 비율 | 분기 | 3% 이하 |
| 담당부서 검수 완료율 | 분기 | 2027. 3. 100% |
| 개정 후 재검수 전 카드 | 월 | 0장(개정 시행 14일 이내 반영) |
| 오류 신고 처리 기간 | 분기 | 7일 이내 |

### 내규 개정 대응
- 내규관리부서가 개정·시행 시 운영부서에 통보
- 운영부서는 개정본을 변환하고 개정 감지 보고서로 영향받는 카드를 확인
  - 인용한 조·항이 바뀐 카드는 화면에 '규정 개정 · 재검수 전'으로 자동 표시
- 소관부서 확인 후 카드 수정·재검증, 새 판 배포(만든 지 90일이 지난 화면은 최신판 확인 안내)

### 중지 기준
- 중대한 오류(직원이 규정을 어기게 만드는 답)가 확인되면 해당 카드를 즉시 내리고 새 판 배포
- 반복 오류나 운영 인력 공백 시 주관부서와 협의해 서비스 중지 검토

## 운영 체계

### 역할
| 역할 | 담당 | 할 일 |
| --- | --- | --- |
| 과제이행·운영 | ○○부서(관리자 ○○○, 대리자 ○○○) | 변환·카드 수정·검증·배포, 오류 신고 처리 |
| 내용 검수 | 각 소관부서 | 분류별 검수표로 카드 검수, 개정 시 재검수 |
| 개정 통보 | 내규관리부서 | 개정·시행 시 운영부서에 통보, 정비 후보 검토 |
| 주관·점검 | AX 주관부서 | 분기 점검, 실무협의회·위원회 보고 |

- 독립 재확인: 로컬 AI 모델(고사양 PC 1대), 카드 작성·수정: 생성형 AI
