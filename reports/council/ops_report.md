# 운영·정보보안·AI 거버넌스 검토 (내규챗봇 시범본)

## 1. 배포 가능성 (망별)

| 환경 | 판단 | 근거 |
|---|---|---|
| 인터넷망 | 가능 | 크롬(맥) 실행 시 화면 준비 0.5초 |
| 폐쇄망 (파일 열기, 사내 웹서버) | **조건부** | 외부 글꼴 주소(fonts.googleapis.com) 1곳을 부르는 줄이 남아 있음. 외부 주소 조회가 바로 실패하는 망은 0.24초로 문제없음. 방화벽이 응답 없이 막는 망에서는 **139초 동안 화면 처리와 검색 기능이 멈춤**(헤드리스 크롬 실측). |
| IE 모드, 구형 엣지 | **불가** | `new Map(배열)`, `normalize`, `replaceChildren`, CSS 변수 사용. 크롬·엣지 86 이상 필요. 사내 포털 주소가 IE 모드 목록에 있으면 동작하지 않음. |
| 저사양 PC | 가능 | 5.5MB 파일. 자료 읽기 21ms, 카드 색인 210ms, 질문 1건 2ms, 메모리 약 65MB(맥 M5 Pro 기준). 4~8배 느린 PC라도 약 1~2초로 추정 |
| 모바일 | 화면 배치는 대응 | 폭 500px에서 가로 넘침 없음. 다만 폐쇄망 문서는 휴대폰에서 접근할 수 없음 |

서버가 없고, 질문을 밖으로 보내지 않으며, 로그와 브라우저 저장소도 쓰지 않습니다. 이 점은 보안상 큰 장점입니다. 확인할 점: 망연계 시스템이 .html 파일을 넘겨 주는지, 문서보안(DRM)이 파일을 암호화하지 않는지.

## 2. 위험과 심각도

- **상** 외부 글꼴 호출: 폐쇄망 멈춤과 외부 통신이 생김. 한 줄만 지우면 해결됩니다.
- **상** 개정 반영 누락: 사본에 개정을 흉내 내 시험했습니다. 복무세칙 제19조 배우자 출산휴가에 "다만, 수습 직원은 10일" 같은 단서를 넣어도 검사 결과는 **오류 0, 경고 0**이고 묶기도 진행됩니다. 인용 문구 속 숫자를 바꾼 경우에만 잡힙니다. 2026년 7~9월에 개정된 16개 규정을 인용한 카드가 **412장(전체의 41%)**입니다.
- **상** 검증 표시 과장: 모든 카드에 초록색 "독립 검증 통과" 표시가 붙습니다. 그런데 사람 검수는 0건이고, '확인 필요' 314건은 만든 쪽 AI가 모두 "카드 유지"로 처리했습니다(그중 152건은 표현 지적). 규정이 개정된 뒤에도 예전 검증 결과가 그대로 표시됩니다.
- **중** 오류 신고 칸: 받는 사람과 부서가 적혀 있지 않습니다. "도움이 됐어요" 버튼은 기록을 남기지 않습니다.
- **중** 규정 정비 후보 14건(법령과 맞지 않는다는 주장 포함)과 검수 메모 331장이 전 직원 화면에 그대로 보입니다.
- **하** 회색 글자의 명암 대비 3.6:1(기준 4.5:1 미달), 인쇄하면 AI 표시가 빠짐, 옛 사본이 유통돼도 경고가 없음.

## 3. 유지보수 현실성

필요한 것: 파이썬, 노드, 인터넷(`npx -y kordoc`, 판이 고정돼 있지 않음), 64GB 맥에서 ollama qwen3.5:35b, 카드 작성용 Claude, JSON 편집 능력. 지금은 이를 갖춘 사람이 1명이고 장비도 1대입니다. 규정 1개가 개정되면 변환 → 검사 → 카드 수정 → 검증 → 시험 → 묶기 → 망연계 배포까지 숙련자 기준으로 1~3시간이 걸린다고 봅니다. 분기마다 규정 16개 정도가 바뀝니다. 아무도 관리하지 않으면 3개월 안에 카드의 약 40%가 옛 규정을 기준으로 답하게 됩니다. 화면 맨 위의 "규정 기준 2026.10.21."은 사람이 직접 적는 값입니다. 만든 날짜도, 오래된 판이라는 경고도 나오지 않습니다(답마다 붙는 "현행 시행일"은 있음).

## 5. 정식 배포 전에 꼭 할 일 5가지

1. 외부 글꼴 줄을 지우고 CSP로 외부 연결을 막습니다. 업무망 엣지에서 실제로 열어 봅니다. IE 모드 목록에 없는 주소에 올리고, 지원하지 않는 브라우저에는 안내 문구를 띄웁니다.
2. 위험 수준 자체평가서와 고영향 해당 여부 확인서를 만들어 AX금융기획실과 사전 협의합니다. 실무협의회에서 세부실행과제로 확정하고, 정보보안담당관 검토를 받습니다. claude.ai 게시를 계속할지도 이때 정합니다.
3. 담당부서가 규정별로 검수하고, 카드마다 검수자와 날짜를 기록합니다. 표시는 "AI 작성·미검수"와 "검수 완료(날짜)"로 나눕니다. 정비 후보와 검수 메모는 직원용 화면에서 빼고 내규관리부서에 따로 넘깁니다.
4. 운영부서·담당자·처리 기한을 정하고 오류 신고 창구(메일함이나 게시판)를 둡니다. 분기마다 점검합니다.
5. 개정 대응 체계를 만듭니다. 내규관리부서가 개정할 때마다 알려 주고, 조문 원문이 바뀌면 그 조문을 인용한 카드를 모두 재검수 대상으로 묶습니다(인용 문구가 일치하는지만 보는 지금 방식으로는 부족). 화면에 만든 날짜를 표시하고, 오래된 판이면 경고합니다. kordoc 판을 고정하고, 원본은 업무용 저장소로 옮기고, 관리자와 대리자를 둡니다.

- 배포 용이성: **3** (글꼴 줄을 고치면 4)

- 규정 준수: **2** (시범 운영 수준이며, 절차를 마치면 4까지 가능)
