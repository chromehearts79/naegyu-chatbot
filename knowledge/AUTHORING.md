# 문답 카드 작성 지침

내규챗봇의 답은 모두 "카드"에서 나온다. 카드 하나 = 직원 질문에 대한 답의 칸 하나. 이 지침은 사람과 AI 작성자 모두에게 적용된다.

## 1. 파일과 이름

- 규정 하나 = 파일 하나: `knowledge/all_rules/<접두어>.json` (예: `r3-2-1.json`). 접두어는 `python3 scripts/show_rule.py <규정명>` 첫 줄에 나온다.
- 카드 id 는 `<접두어>-<영문 소문자 하이픈>` (예: `r3-2-1-promotion-years`). 전체에서 겹치면 안 된다.
- 시험 질문: `knowledge/all_rules/_devset_<접두어>.json`. 형식은 `{"items": [{"q": "질문", "expect": ["카드 id"]}]}`. 규정마다 2~4개를 쓰되, 카드의 `questions`와 다른 표현으로 쓴다(시험지를 미리 보여주지 않기 위해).

## 2. 카드 형식 (JSON 배열의 원소)

```json
{
  "id": "r4-1-card-loss",
  "rule": "법인카드 관리 및 사용지침",
  "topics": ["g5"],
  "title": "법인카드 분실·도난 시 조치",
  "summary": "한두 문장 요약. 검색 결과 목록과 되묻기 버튼에 그대로 보인다.",
  "answer": ["문단1", "문단2"],
  "facts": [
    {"label": "짧은 항목명", "value": "짧은 값", "cite": "법인카드 관리 및 사용지침 제8조제1항", "quote": "원문 그대로의 문구"}
  ],
  "related": ["관련 카드 id (다른 규정의 같은 주제 카드도 가능)"],
  "questions": ["직원이 칠 법한 질문 6~10개"],
  "keywords": ["핵심어 묶음 1~3개"],
  "check": ["담당부서가 확인할 점(있으면)"]
}
```

- 규정마다 **개요 카드 1장**을 맨 앞에 둔다. `"overview": true`, 제목은 `"<규정명> 개요"`. 무엇을 정한 규정인지, 적용 범위, 주관 부서(원문에 있으면), 이 규정의 다른 카드로 가는 `related`(전부)를 담는다.
- `topics` 는 그 규정이 속한 묶음 id 하나(g1~g10).
- 선택 필드: `"calc"`는 쓰지 않는다. `"kind": "outside"`는 쓰지 않는다(규정 전체 분야에서는 불필요).
- `"calc_link"`: 금액·기간을 다루지만 계산기가 없는 카드에 관련 계산기 이름(예: `"tripExpense"`)을 적으면 '계산기 열기' 버튼이 붙는다. 이름은 `knowledge/calc_basis.json` 에 있는 것만.

## 3. 근거(facts) 규칙 — 자동 검사가 확인한다

- `cite` 형식: `규정명 제N조`, `규정명 제N조제N항`, `규정명 제N조제N항제N호`, `…제N호가목`, `규정명 별표 제N호`(별표 제목 앞부분), `규정명 부칙(YYYY.MM.DD)`.
- `quote` 는 인용 위치(항·호·목까지 적었으면 그 범위) 원문에 **글자 그대로** 있어야 한다. 원문을 복사해 붙인다. 띄어쓰기와 가운뎃점 차이는 허용된다.
- `value` 에 쓴 숫자는 인용 위치 원문에 있어야 한다. 다른 조문에 있는 숫자면 그 조문을 인용하는 사실을 따로 만든다.
- `answer` 문단의 숫자도 카드가 인용한 조문들 안에 있어야 한다(경고).
- 원문에 없는 내용은 쓰지 않는다. 해석이 필요하거나 애매하면 답에 "관련 부서에 문의하세요"를 적고 `check`에 이유를 남긴다.
- 문의처 안내는 부서 이름을 짐작해 쓰지 않고 **"관련 부서에 문의하세요"**로만 쓴다(인사팀·인사 담당·회계 담당·정보보안 담당부서·담당부서(복무) 등 금지, 짐작한 부서가 틀린 경우가 많았다). 내규가 정한 역할 이름(행동강령책임관, 카드관리담당자, 상담원 등)과 외부 기관(고용센터 등)은 써도 된다. `check_knowledge.py` 가 이 규칙을 검사한다(계산기 안내 web/engine.js 포함).

## 4. 무엇을 카드로 만드나

- 직원이 물을 수 있는 실질 내용(기간, 금액, 요건, 절차, 금지, 예외, 신청 방법, 담당, 기한)이 있는 조문은 빠짐없이 카드로 만든다. 관련 조문 2~3개를 한 카드로 묶어도 된다(대략 조문 1~3개당 카드 1장).
- "목적", "시행일" 같은 조문은 개요 카드에만 담는다. "정의"는 직원이 헷갈릴 만한 용어만 카드로 만든다.
- 별표(금액표, 기준표)는 핵심 내용을 카드로 만든다. 별지 서식은 "어떤 서식을 쓰는가" 정도만 답에 언급한다.
- `show_rule.py` 가 "[이미 다룸]"으로 표시한 조문은 다른 분야 카드가 이미 답한다. 새 카드를 만들지 말고 관련 카드의 `related` 에 그 카드 id 를 넣는다.

## 5. 문장

- 쉬운 우리말, 짧은 문장, "~합니다/입니다". 한 카드의 `answer` 는 2~5문단.
- 핵심 숫자·조건은 `**굵게**`. 법령 문체를 그대로 옮기지 말고 직원이 이해할 말로 풀되, 뜻을 바꾸지 않는다.
- `questions` 는 규정 용어형, 일상어형("~돼요?", 반말 포함), 상황 설명형, 짧은 애매형을 섞는다. 다른 카드와 같은 문장은 쓰지 않는다.
- 검색은 카드 전체 글자를 본다. 직원이 쓸 법한데 카드에 없는 일상어·약어(투잡, 법카, 칼퇴 등)는 `keywords` 에 한 줄로 더한다.
- `_devset*.json` 시험 질문은 열어 보지 않는다. 보고 비슷하게 쓰면 정확도 측정이 부풀려진다.

## 6. 검사

```bash
python3 scripts/check_knowledge.py knowledge/all_rules/<접두어>.json
```

오류 0건이 될 때까지 고친다. 경고도 가능한 한 없앤다.
