# 내규가 바뀌었을 때: 내규챗봇 유지보수 안내

## 한 장 요약

```
① 새 파일 넣기  →  ② 변환·비교  →  ③ 카드 고치기  →  ④ 승인·새 판 만들기  →  ⑤ 배포·기록
   (사람)            (자동)           (AI)               (사람 승인 → 자동)      (사람)
```

내규챗봇의 답은 모두 미리 써 둔 **문답 카드**에서 나온다. 카드는 내규 조문을 근거로 쓰였고, 어느 조문의 어느 글자를 근거로 했는지 기록돼 있다. 그래서 내규가 바뀌면 **바뀐 조문을 근거로 쓴 카드만** 골라 고치면 된다. 그 골라내기는 프로그램이 하고, 고쳐 쓰기는 AI(Claude)가 하고, 사람은 확인하고 승인한다.

## 이럴 때 이렇게

| 상황 | 할 일 |
|---|---|
| 기존 내규가 개정됨 | 개정본 한글 파일을 내규 폴더에 넣고, 옛 파일은 `지난판` 폴더로 옮긴다(같은 이름이면 덮어써도 된다). |
| 새 내규가 생김 | 새 파일을 `코드. 규정명.hwp` 이름으로 넣는다. 예: `Ⅳ-30. ○○지침.hwp`(코드는 내규분류표 위치). |
| 내규가 폐지됨 | 그 파일을 `지난판` 폴더로 옮긴다. 관련 카드는 3단계에서 정리된다. |
| 별표(위임전결기준 엑셀 등)만 바뀜 | 바뀐 파일만 교체한다. 별표 표를 근거로 쓴 카드가 골라진다. |
| 규정 이름만 바뀜 | 새 이름으로 파일을 바꿔 넣는다. 같은 코드면 같은 규정으로 알아본다. |

내규 폴더: iCloud Drive › 내규챗봇 (`[개정근거]`처럼 `[`로 시작하는 참고 파일과 `지난판` 폴더는 읽지 않는다)

## 시작하는 방법

Claude(Code 탭)에서 아래 중 하나로 말한다.

- 파일을 대화창에 끌어다 놓고 **"내규 개정 반영해줘"**
- 파일을 내규 폴더에 직접 넣었다면 **"내규 개정 반영"**

그러면 Claude가 단계마다 결과를 짧게 설명하고, 아래에 **다음 단계 버튼**을 띄운다. 버튼만 누르면 다음 단계로 넘어간다.

## 단계별로 무슨 일이 일어나나

**1단계: 파일 확인 (몇 초)**
- 지난번과 비교해 바뀐 파일, 새 파일, 사라진 파일을 보여 준다.
- 같은 규정 파일이 두 개 있거나 이름 형식이 틀리면 알려 주고, 원하면 대신 정리한다.
- 버튼: `변환하고 비교하기`

**2단계: 변환·비교 (1~3분, 자동)**
- 바뀐 파일만 한글에서 글로 바꾸고, 조문 하나하나를 지난번 원문과 비교한다.
- 보여 주는 것:
  - 시행일이 바뀐 규정
  - 바뀐 조문의 개정 전·후 글자
  - 다시 확인할 카드 수
  - 다시 확인할 계산기(출장 여비·가족수당처럼 숫자를 계산하는 기능의 근거 조문이 바뀐 경우)
  - 새로 생긴 조문
  - 카드가 아직 없는 새 내규
  - 양식(별지) 변화: 별지 제목·번호가 바뀐 것, 별지를 부르는 조문이 바뀐 것, 조문이 부르는 이름과 별지 제목이 달라 양식 칸을 달지 않은 곳
- 같은 항에 "다만, …" 같은 단서가 새로 붙은 것도 잡는다.
- 버튼: `카드 고치기 시작`

**3단계: 카드 고치기 (AI, 규모에 따라 수 분~수십 분)**
- 바뀐 조문을 근거로 쓴 카드의 답과 근거를 새 원문대로 고친다.
- 계산기 숫자의 근거 조문이 바뀌었으면 계산기 숫자도 새 원문대로 고친다(예: 식비 25,000원 → 30,000원). 숫자가 원문과 다르면 검사가 오류로 막는다.
- 새 조문과 새 내규는 카드를 새로 만든다.
- 법령 개정 때문에 바뀐 것이면 국가법령정보로 상위 법령도 확인한다.
- 원문 대조 검사와 다른 AI 재확인까지 거친다.
- 보여 주는 것: 카드마다 "무엇이 바뀌었나" 한 줄(예: "외부위원 2명 내외 → 3명 이내"), 담당부서 확인이 필요한 점
- 버튼: `반영 승인` 또는 `고칠 점 말하기`

**4단계: 승인·새 판 만들기 (자동, 1~2분)**
- 승인한 내용으로 시범본 화면(`dist/index.html`)과 인터넷망 지식 묶음, 검수표를 다시 만든다.
- 판 번호가 하나 올라간다(화면 맨 위 "제N판"). 직원이 가진 옛 사본과 구별하는 표시다.
- 내규나침반의 낱말 경계도 바뀐 원문에 맞춰 다시 만든다. 형태소 분석기가 필요해 처음 한 번은 설치한다(인터넷 필요, 약 100MB). 분석은 이 PC에서만 하고 폐쇄망 화면에는 결과만 들어간다.
- 양식(별지)을 원본 한글 파일에서 한 장씩 다시 떼어 내고, 떼어 낸 양식이 원본 별지와 같은지 검사한다. 다른 양식이 있으면 멈추고 알려 준다(그 양식만 받기를 끄고 다시 만든다).
- 화면 점검을 돌린다.
- claude.ai 시범본을 쓰고 있다면 같은 주소에 다시 올릴지 묻는다.
- 버튼: `커밋하기`

**5단계: 배포·기록 (사람)**
- 새 `index.html` 을 사내 게시판·공유폴더에 새 판으로 올린다. 옛 판은 내리고, 게시글 제목에 판 번호를 적는다.
- 바뀐 카드가 든 검수표를 소관부서에 보내 검수를 받는다.

## 그동안 화면은 어떻게 보이나

- 개정본을 넣고 아직 카드를 다 고치지 않은 상태에서 화면을 다시 만들면, 바뀐 조문을 근거로 쓴 답에 **"규정 개정 · 재검수 전"** 표시와 바뀐 조문 번호가 붙는다. 직원이 옛 기준으로 오해하지 않게 하기 위한 안전장치다.
- 계산기 숫자의 근거 조문이 바뀌었는데 아직 고치지 않았으면, 그 계산기는 **"근거 조문이 개정돼 … 계산하지 않습니다"**로 멈춘다.
- 화면을 만든 지 90일이 지나면 위쪽에 "최신판인지 확인하세요" 안내가 뜬다(설정에서 일수 변경 가능).
- 개정된 내규의 양식은 4단계에서 새 원본으로 다시 떼기 전까지 받기에서 빠진다(옛 원문의 양식이 나가지 않게).

## 양식(별지) 받기

- 직원은 조문 아래나 내규나침반 맨 위의 **'양식'** 칸에서 별지를 한글 파일로 받는다. 파일은 내규 원본에서 그 별지만 떼어 낸 것이라 원본과 모양이 같다.
- 어떤 별지가 있고 어느 조문이 부르는지는 **서식 대장**(`knowledge/forms.json`)에 적혀 있다. 2단계에서 바뀐 내규만 원문에서 다시 읽고, 사람이 고친 제목·받기 켜고 끄기는 그대로 둔다.
- 받기를 끄려면 그 별지의 `download` 를 `false` 로 바꾸고 `cutNote` 에 까닭을 적는다(예: 앞 양식과 한 덩어리로 얽혀 깨끗하게 뗄 수 없음).
- 조문이 부르는 이름과 별지 제목이 다르면(원문의 번호가 틀렸을 수 있음) 그 조문에는 양식 칸을 달지 않는다. 내규관리부서에 원문 확인을 부탁한다.
- 조문이 법령 이름 바로 뒤에서 별지를 불러도(예: "「…시행규칙」 제9조에 의하여 별지 제16호 서식의 …") 그 내규 끝에 같은 번호 별지가 있으면 내규 별지로 보고 양식 칸을 단다. 내규 끝에 그 번호가 없을 때만 법령 서식으로 보고 칸을 달지 않는다.
- 부르는 조문이 없는 별지는 이름으로 찾을 때만 뜬다. 이름이 다른 별지와 겹치면 띄우지 않는데, 겹치는 별지들이 모두 같은 종이(원문 글이 같음)면 함께 띄운다(예: 평가세칙·전임전문직원관리세칙의 연봉등급 승급 평가표).

## 계산기에서 틀린 금액이 신고되면

시범 운영 중 계산기가 틀린 금액·기간을 냈다는 신고가 **1건이라도** 들어오면 그 계산기를 바로 끈다.

1. Claude 에게 "출장 여비 계산기 꺼줘"라고 말한다(설정 `knowledge/site.json` 의 `calcOff` 에 넣고 새 판을 만든다).
2. 새 판을 올린다. 그 계산기는 "점검 중이라 계산하지 않습니다"로 바뀌고, 답과 근거 조문은 그대로 보인다.
3. 원인을 고치고 담당부서 확인을 받은 뒤 다시 켠다.

## 매주 ALIO 확인

ALIO(공공기관 알리오)에 올라온 우리 기관 내규가 우리가 가진 판과 달라졌는지 컴퓨터가 매주 월요일 9시(PC가 꺼져 있었으면 다음 로그인 때)에 확인한다. AI는 쓰지 않고, 아무것도 밖으로 보내지 않는다. **윈도우 PC로 옮긴 뒤에 시작한다.** 지금 맥에서는 돌지 않는다.

**어디서 보나**
- 달라진 것이 있으면 윈도우 알림이 뜨고 `문서\내규챗봇 ALIO 확인\이번 주 결과.html` 이 열린다. 달라진 게 없으면 "이번 주 변동 없음" 알림만 뜬다.
- 같은 폴더에 지난 결과(`기록` 폴더), 내규별로 처음 잡힌 날과 해소된 날(`기록.csv`), ALIO에서 받은 파일(`대기` 폴더)이 있다. `기록.csv` 를 엑셀로 열어 둔 채면 기록을 쓰지 못하니 닫아 둔다(결과 화면에 그렇게 표시된다).

**결과 화면의 판정과 할 일**

| 화면의 판정 | 뜻 | 할 일 |
|---|---|---|
| 변동 없음 | 그대로다 | 없음(알리지도 않는다) |
| 이미 반영 | ALIO 파일이 우리 판과 같다 | 없음 |
| 글자 변화 없음 | 파일은 다시 올렸지만 글자는 같다(재게시) | 없음. 다음 새 판을 만들 때 기록이 함께 올라간다 |
| 배포 대기 | 새 파일을 이미 반영해 새 판을 만들었지만 아직 배포 전이다 | 새 판을 배포한다 |
| 조문 밖 변화 | 조문·별표·부칙은 같은데 별지 등 다른 글자가 달라졌다 | 달라진 글자를 보고, 반영할 내용이면 아래 '개정 반영', 아니면 '확인함' |
| 개정 의심 | ALIO 파일이 우리 판과 다르다 | 비교 결과를 보고 '개정 반영'. 반영할 게 없으면 '확인함' |
| 담당자 확인 | 컴퓨터가 어느 파일이 현행인지 가릴 수 없었다(까닭이 적혀 있다) | 받은 파일을 직접 보고 반영하거나 '확인함' |
| 새 내규 | 우리 판에 없는 내규가 ALIO에 있다 | 넣을 것이면 '개정 반영'(새 내규 추가), 넣지 않기로 하면 '확인함' |
| 목록에서 사라짐 | 우리 판에는 있는데 ALIO 목록에 없다. 폐지라고 단정하지는 않는다 | 폐지됐는지 알아보고, 유효하면 '확인함' |
| 확인 실패 | 인터넷이나 사이트 문제 등으로 확인하지 못했다. "변동 없음"이 아니다 | 까닭을 보고 다음 로그인 때 다시 도는지 본다. 계속되면 개발자에게 알린다 |

- **개정 반영:** 화면에 적힌 "받은 파일 위치"(`대기` 폴더)의 파일을 "원본 폴더에 넣을 이름" 그대로 내규 폴더(iCloud 내규챗봇)에 넣는다. 옛 파일은 `지난판` 폴더로 옮긴다. 그다음 Claude에게 "내규 개정 반영"이라고 말한다. 새 판을 올리면 알림은 다음 확인 때 저절로 사라진다.
- **확인함:** ALIO 파일을 반영하지 않기로 했거나 이미 다른 파일로 반영해서 알림만 끝내고 싶을 때 쓴다. 정 담당 PC의 `확인함.bat` 을 더블클릭하고, 번호를 고르고, 까닭을 한 줄 적는다. 그 까닭과 날짜가 기록에 남고, **끝낸 표시는 다음에 새 판을 올릴 때 함께 나간다**(판 번호는 오르지 않는다). 그 뒤 ALIO 값이 또 바뀌면 처음부터 다시 판정한다. '배포 대기'와 '확인 실패'는 확인함으로 끝낼 수 없다.
- **14일 빨간 표시:** 알림이 14일 넘게 끝나지 않은 내규는 경과일이 빨간색으로 나오고 "정 담당 확인, 부재면 게시판에 미반영 공지"라고 적힌다. 정 담당이 확인하고, 자리에 없으면 게시판에 "ALIO에 올라온 ○○ 개정이 아직 챗봇에 반영되지 않았다"는 **미반영 공지**를 올린다.

**설치 (한 번만)**
- 파이썬 3.11 이상이 있는 PC에서 한다.
- 정 담당 PC(저장소가 있는 PC): `python -X utf8 scripts/install_watch.py --mode full --repo <저장소 폴더>`
- 부 담당 PC(저장소 없음): 정 담당이 `python -X utf8 scripts/install_watch.py --pack 부담당.zip` 으로 묶음을 만들어 주면, 압축을 풀고 `python -X utf8 install_watch.py --mode alert --url <배포판 목록 주소(release.json)>` 를 돌린다. 부 담당 PC는 알림과 결과만 보고, 비교는 "정 담당 PC에서 비교"로 표시된다.
- 먼저 `--dry-run` 을 붙이면 파일만 만들고 등록은 하지 않는다. 윈도우 작업 스케줄러에 `내규챗봇 ALIO 확인` 이 생기고, 설정 파일은 `문서\내규챗봇 ALIO 확인\config.json` 이다.
- **아직 윈도우에서 등록해 본 적이 없다.** 윈도우로 옮긴 뒤 처음 설치할 때, 작업이 생겼는지와 알림이 뜨는지, 회사 인터넷에서 ALIO에 닿는지를 직접 확인한다.

## 문제가 생기면

| 메시지 | 뜻과 할 일 |
|---|---|
| 같은 코드 파일이 2개 | 개정 전 파일이 남아 있음 → `지난판` 폴더로 옮긴다 |
| 이름이 '코드. 규정명' 형식이 아님 | 파일 이름을 `Ⅳ-30. ○○지침.hwp` 처럼 바꾼다 |
| 카드 검사 오류 N건 | 조문 번호가 바뀌거나 삭제돼 인용이 깨진 카드. 3단계에서 Claude가 고친다 |
| 변환 실패 | 한글 파일이 암호·DRM으로 잠겨 있을 수 있음 → 잠금 없는 파일로 다시 받는다 |
| [계산기 …] 원문에 "…" 가 없음 | 계산기 숫자의 근거 문구가 개정으로 바뀜. 3단계에서 Claude가 계산기 숫자와 근거표를 새 원문대로 고친다 |
