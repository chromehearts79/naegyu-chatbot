# 내규가 바뀌었을 때: 내규챗봇 유지보수 안내

## 한 장 요약

```
① 새 파일 넣기  →  ② 변환·비교  →  ③ 카드 고치기  →  ④ 승인·새 판 만들기  →  ⑤ 배포·기록
   (사람)            (자동)           (AI)               (사람 승인 → 자동)      (사람)
```

내규챗봇의 답은 모두 미리 써 둔 **문답 카드**에서 나온다. 카드는 내규 조문을 근거로 쓰였고, 어느 조문의 어느 글자를 근거로 했는지 기록돼 있다. 그래서 내규가 바뀌면 **바뀐 조문을 근거로 쓴 카드만** 골라 고치면 된다. 그 골라내기는 프로그램이 하고, 고쳐 쓰기는 AI(Claude)가 하고, 사람은 확인하고 승인한다.

## 이럴 때 이렇게

| 상황 | 할 일 |
|---|---|
| 기존 내규가 개정됨 | 개정본 한글 파일을 내규 폴더에 넣고, 옛 파일은 `지난판` 폴더로 옮긴다(같은 이름이면 덮어써도 된다). |
| 새 내규가 생김 | 새 파일을 `코드. 규정명.hwp` 이름으로 넣는다. 예: `Ⅳ-30. ○○지침.hwp`(코드는 내규분류표 위치). |
| 내규가 폐지됨 | 그 파일을 `지난판` 폴더로 옮긴다. 관련 카드는 3단계에서 정리된다. |
| 별표(위임전결기준 엑셀 등)만 바뀜 | 바뀐 파일만 교체한다. 별표 표를 근거로 쓴 카드가 골라진다. |
| 규정 이름만 바뀜 | 새 이름으로 파일을 바꿔 넣는다. 같은 코드면 같은 규정으로 알아본다. |

내규 폴더: iCloud Drive › 내규챗봇 (`[개정근거]`처럼 `[`로 시작하는 참고 파일과 `지난판` 폴더는 읽지 않는다)

## 시작하는 방법

Claude(Code 탭)에서 아래 중 하나로 말한다.

- 파일을 대화창에 끌어다 놓고 **"내규 개정 반영해줘"**
- 파일을 내규 폴더에 직접 넣었다면 **"내규 개정 반영"**

그러면 Claude가 단계마다 결과를 짧게 설명하고, 아래에 **다음 단계 버튼**을 띄운다. 버튼만 누르면 다음 단계로 넘어간다.

## 단계별로 무슨 일이 일어나나

**1단계: 파일 확인 (몇 초)**
- 지난번과 비교해 바뀐 파일, 새 파일, 사라진 파일을 보여 준다.
- 같은 규정 파일이 두 개 있거나 이름 형식이 틀리면 알려 주고, 원하면 대신 정리한다.
- 버튼: `변환하고 비교하기`

**2단계: 변환·비교 (1~3분, 자동)**
- 바뀐 파일만 한글에서 글로 바꾸고, 조문 하나하나를 지난번 원문과 비교한다.
- 보여 주는 것:
  - 시행일이 바뀐 규정
  - 바뀐 조문의 개정 전·후 글자
  - 다시 확인할 카드 수
  - 새로 생긴 조문
  - 카드가 아직 없는 새 내규
- 같은 항에 "다만, …" 같은 단서가 새로 붙은 것도 잡는다.
- 버튼: `카드 고치기 시작`

**3단계: 카드 고치기 (AI, 규모에 따라 수 분~수십 분)**
- 바뀐 조문을 근거로 쓴 카드의 답과 근거를 새 원문대로 고친다.
- 새 조문과 새 내규는 카드를 새로 만든다.
- 법령 개정 때문에 바뀐 것이면 국가법령정보로 상위 법령도 확인한다.
- 원문 대조 검사와 다른 AI 재확인까지 거친다.
- 보여 주는 것: 카드마다 "무엇이 바뀌었나" 한 줄(예: "외부위원 2명 내외 → 3명 이내"), 담당부서 확인이 필요한 점
- 버튼: `반영 승인` 또는 `고칠 점 말하기`

**4단계: 승인·새 판 만들기 (자동, 1~2분)**
- 승인한 내용으로 시범본 화면(`dist/index.html`)과 인터넷망 지식 묶음, 검수표를 다시 만든다.
- 화면 점검을 돌린다.
- claude.ai 시범본을 쓰고 있다면 같은 주소에 다시 올릴지 묻는다.
- 버튼: `커밋하기`

**5단계: 배포·기록 (사람)**
- 새 `index.html` 을 사내 게시판·공유폴더에 새 판으로 올린다.
- 바뀐 카드가 든 검수표를 소관부서에 보내 검수를 받는다.

## 그동안 화면은 어떻게 보이나

- 개정본을 넣고 아직 카드를 다 고치지 않은 상태에서 화면을 다시 만들면, 바뀐 조문을 근거로 쓴 답에 **"규정 개정 · 재검수 전"** 표시와 바뀐 조문 번호가 붙는다. 직원이 옛 기준으로 오해하지 않게 하기 위한 안전장치다.
- 화면을 만든 지 90일이 지나면 위쪽에 "최신판인지 확인하세요" 안내가 뜬다(설정에서 일수 변경 가능).

## 얼마나 자주, 누가

| 역할 | 할 일 | 시점 |
|---|---|---|
| 내규관리부서 | 개정·신설 내규 파일을 관리자에게 전달 | 개정 공포 때 |
| 관리자(내규챗봇 담당) | 1~5단계 진행(버튼), 배포 | 시행일 전후 14일 안 |
| 소관부서 | 바뀐 카드 검수표 확인 | 배포 후 |

- 개정 1건은 보통 30분~1시간이면 반영된다. 새 내규는 조문 수에 따라 더 걸린다.
- 필요한 것: 이 맥 1대(변환·검사 프로그램과 로컬 검증 AI가 설치돼 있음), Claude.
- 관리자가 바뀌면 이 안내서와 `README.md`, `knowledge/AUTHORING.md` 를 넘겨준다.

## 문제가 생기면

| 메시지 | 뜻과 할 일 |
|---|---|
| 같은 코드 파일이 2개 | 개정 전 파일이 남아 있음 → `지난판` 폴더로 옮긴다 |
| 이름이 '코드. 규정명' 형식이 아님 | 파일 이름을 `Ⅳ-30. ○○지침.hwp` 처럼 바꾼다 |
| 카드 검사 오류 N건 | 조문 번호가 바뀌거나 삭제돼 인용이 깨진 카드. 3단계에서 Claude가 고친다 |
| 변환 실패 | 한글 파일이 암호·DRM으로 잠겨 있을 수 있음 → 잠금 없는 파일로 다시 받는다 |
