# 내규챗봇 윈도우 이전 설계

- 작성일: 2026-11-04
- 상태: **쓰지 않음.** 사용자가 브라우저 방식을 골라 `2026-11-05-browser-ops-design.md` 로 대체됨(2026-11-05)
- 범위: 인계 과제 중 2번. 프로그램과 자료를 GitHub로 옮기고, 담당자의 윈도우 외부망 PC에서 설치부터 개정 반영까지 돌게 만든다.
- 앞선 설계: `docs/superpowers/specs/2026-11-04-alio-watch-design.md`(1번 ALIO 확인 루틴, main 반영됨)

## 1. 왜 만드나

내규챗봇 유지보수를 담당자에게 넘기려 한다. 그런데 지금은 프로그램과 문답 세트가 이 맥 한 대에만 있고, 내규 원본은 만든 사람의 iCloud에 있고, 재확인 AI는 이 맥의 큰 로컬 모델로 돈다. 담당자는 개발자가 아니고 윈도우 PC를 쓴다.

그래서 담당자가 **파일 하나를 더블클릭하면 준비가 끝나고**, 그 PC가 고장 나도 새 PC에서 그대로 이어 갈 수 있게 만든다.

## 2. 목표와 하지 않을 일

**목표**
- 담당자가 윈도우 PC에서 설치 파일 하나로 전부 준비한다.
- 개정 반영 5단계가 윈도우에서 돈다. 맥에서도 계속 돈다.
- 사본이 GitHub에 있어 PC가 고장 나도 복구된다.
- 담당자의 Claude가 이 프로젝트의 주의점을 저장소에서 읽을 수 있다.
- 시험을 GitHub Actions의 윈도우에서 자동으로 돌린다.

**하지 않을 일**
- Vercel 배포와 망연계(3번 과제), 인터넷망 보완 요청 받기(4번 과제).
- 문답 세트 내용이나 검색 동작 변경.
- 카드를 다시 쓰는 일. 윈도우로 옮겼다는 이유로 문답이 하나라도 "다시 확인"으로 잡히면 안 된다.
- AI를 골라 쓰는 기능(Claude API, GPT API, 로컬 모델, `AI_설정.bat`). 다음 과제로 만든다(10장). 이번에는 재확인의 문제·답을 파일로 주고받게 해서 나중에 바꿔 끼울 수 있게만 해 둔다.

**이렇게 되면 돌아가도 실패다**
- 옮기고 나니 개정이 없는데 문답이 "재검수 전"으로 잡힌다.
- 비개발자가 설치 도중 명령을 쳐야만 넘어갈 수 있다.
- `[개정근거]` 시행문처럼 직원 정보가 든 파일이 GitHub에 올라간다.
- 맥과 윈도우에서 같은 원본으로 다른 결과가 나오는데 아무도 모른다.

## 3. 정해진 것

| 내용 | 근거 |

| 문답 세트 고치기는 담당자 PC의 Claude(20달러 Pro 계정)로 한다 | 사용자 결정 |

## 4. 확인한 사실(2026-11-04)

**kordoc 판이 결과를 바꾼다.** 원본 72개를 판별로 다시 변환해 현재 `data/md` 와 지문(`knowledge/source_snapshot.json`)에 비교했다.

| 판 | 글자까지 같은 변환본 | 지문 대비 바뀐 단위 | 다시 확인 문답 |
|---|---|---|---|
| **4.24.1** | **72/72** | **0** | **0** |
| 4.18.2 | 70/72 | 5(상벌세칙 제15조) | 1 |
| 4.24.42(최신) | 15/72 | 10(6개 내규의 항 나누기가 어긋남) | 0 |

- 최신판은 조문 머리를 굵게 표시하고 항 앞에 공백을 넣어, `build_db.py` 의 항 나누기가 어긋난다.
- kordoc은 하루에도 여러 판이 나온다(4.24.40~42가 2일 사이).
- `scripts/update_rules.py:125` 와 `scripts/convert.sh` 는 판을 고정하지 않아(`npx -y kordoc`), 지금도 다음 개정 반영 때 헛변화가 생긴다.
- `scripts/alio_compare.py` 의 `KORDOC = "kordoc@4.24.42"` 는 지문을 만든 판과 달라 잘못 고정된 값이다. 1번 과제에서 고른 값이며 이번에 바로잡는다.

**맥에 묶인 곳**
- `scripts/update_rules.py:25`, `scripts/cut_forms.cjs:9`, `scripts/convert.sh:5`: iCloud 경로(`NAEGYU_SRC` 로 바꿀 수 있음)
- `scripts/update_rules.py:43,186`: `.venv/bin/python`
- `scripts/blind_check.py:20-27`: `localhost:11434` 의 로컬 모델 `qwen3.5:35b`
- `skills/naegyu-update/SKILL.md:8`, `docs/유지보수_안내.md:22,147`, `README.md`: 맥·iCloud 전제 문구
- 인코딩 지정 없이 파일을 읽고 쓰는 곳이 스크립트 16개에 있다. 한국어 윈도우 기본값(cp949)에서 깨진다.
- `update_rules.py` 의 `run("npx", ...)` 는 윈도우에서 `npx.cmd` 를 찾지 못한다.

**필요한 도구**
- 파이썬 표준 라이브러리 외: `kiwipiepy==0.24.1`, `kiwipiepy_model==0.24.0`(`build_bounds`), `openpyxl`(`review_workbook`), `fontTools`·`brotli`(`make_fonts`. 글꼴은 `web/fonts` 에 이미 있어 일상 작업에는 필요 없음)
- Node.js: `jsdom@24.1.3`, `cfb@1.2.2`(`cut_forms`, `ui_test`), kordoc

**자료 크기와 점검**
- 저장소: 추적 파일 255개, `.git` 11MB. 원본: 72개 약 6MB. `data/` 12MB, `.venv` 167MB, `dist/` 23MB(모두 저장소 밖).
- 추적 파일과 기록에서 메일·전화번호·주민번호 꼴·비밀 키를 찾지 못했다(사람 이름은 찾아보지 않음). 커밋 작성자에 사용자의 개인 메일이 있고, 사용자에게 알렸다.
- 저장소 밖에 다른 작업의 파일이 있다: `knowledge/contacts.json`, `reports/contacts/`, `scripts/contacts_report.py`. 이번 작업에 포함하지 않는다.
- 원격 저장소가 없다. GitHub CLI는 `chromehearts79` 계정으로 로그인돼 있다.

**Claude 사용 한도**
- Pro 플랜에 Claude Code가 포함된다. 5시간 한도와 주간 한도가 있고 채팅과 함께 쓴다. 넘으면 사용 크레딧을 켤 수 있다. API는 별도로 알고 있어, 스크립트가 직접 AI를 부르는 구조는 쓰지 않는다.

## 5. 어떻게 바꾸나

### 5.1 kordoc 판 고정(가장 먼저)

- 판을 한 곳에 정한다. 값은 `4.24.1`.
- `update_rules.py`, `convert.sh`, `alio_compare.py` 가 모두 그 값을 쓴다.
- 저장소 `node_modules` 에 설치해 쓰고, 없으면 고정 판 `npx` 로 받는다(`alio_compare.kordoc_cmd` 의 방식).
- 판을 올리는 절차를 안내서에 적는다. 전체를 다시 변환해 바뀐 단위를 보고 지문을 다시 찍는 일이라 담당 개발자 일이다.
- 이 수정 뒤 복무세칙 직전 판 시험 수치(ALIO 설계 5장)를 다시 재고, 달라지면 그 설계의 숫자를 고친다. 직전 판은 ALIO 복무세칙 ZIP의 `복무세칙(2025년도 10월 30일 개정).hwp` 이고, 공개 자료라 임시 폴더로 받아 쓴다.

### 5.2 저장소와 GitHub

- 비공개 저장소 `naegyu-chatbot` 을 `chromehearts79` 계정에 만든다. 담당자가 정해지면 초대하거나 저장소를 넘긴다.
- **원본을 저장소에 넣는다:** `원본/` 폴더. `[` 로 시작하는 파일은 넣지 않는다(`.gitignore` 로도 막는다).
- 줄바꿈 변환으로 지문이 바뀌지 않게 `.gitattributes` 로 변환을 끈다(`* -text`). `.bat` 등 CRLF가 필요한 파일은 CRLF로 저장한 채 올린다.
- `data/`, `dist/`, `node_modules/`, `.venv/`, `도구/` 는 계속 저장소 밖이다. 설치 프로그램이 만든다.
- **올리기 전 점검(프로그램):** `scripts/check_upload.py`. 올릴 파일 전체(원본 변환본 포함)에서 메일, 전화번호, 주민번호 꼴을 찾고, 원본의 파일 정보(작성자 등)를 목록으로 낸다. 전화번호는 알려진 공개 번호 2건(개인정보보호세칙의 예시 번호, 부정청구 지침의 공공기관 번호)만 통과시키고 나머지는 멈춘다. 원본은 지문이 바뀌지 않게 파일 정보까지 그대로 올린다. 2026-11-05 점검에서 파일 정보의 값은 일반 값(Administrator, PoSiD, user 등)과 기관명·문서 제목이었고, 사람 이름으로 보이는 값은 1건(개인정보보호세칙)인데 ALIO 공개본에도 같은 값이 있다.
- **올리기 전 확인(사람):** 저장소 이름, 비공개 여부, 파일 목록과 점검 결과를 사용자에게 보여 주고 허락을 받은 뒤 올린다. 이 단계는 건너뛰지 않는다.
- **올린 뒤 확인(프로그램):** GitHub에 올라간 파일 목록에 `[개정근거]`, `contacts` 가 없는지 본다.
- 기록은 그대로 올린다(작성자 메일 포함, 사용자에게 알린 사항).

### 5.3 원본 폴더 기준 바꾸기

- `NAEGYU_SRC` 가 없으면 `<저장소>/원본` 을 쓴다. iCloud 경로 기본값을 없앤다.
- 이 맥의 iCloud `내규챗봇` 폴더는 지우지 않고 보관본으로 둔다. 안의 `설계문서`, `시험판` 도 그대로 둔다. 이후 원본의 기준은 저장소다.
- 주간 확인의 대기 폴더(`문서\내규챗봇 ALIO 확인\대기`)에서 `원본/` 으로 넣는 흐름으로 안내서를 고친다.

### 5.4 윈도우에서 돌게 고치기

- 파일 읽기·쓰기는 UTF-8로 동작하게 한다. 설치 프로그램이 사용자 환경 변수 `PYTHONUTF8=1` 을 넣고, 예약 작업과 하위 실행에는 `-X utf8` 을 넘긴다.
- `.venv` 경로, `npx`·`node` 호출을 맥·윈도우 모두 되게 한다.
- `git config core.longpaths true` 를 설치 때 켠다.
- 파일 이름은 NFC로 맞춰 비교한다.
- 맥의 동작과 결과는 달라지지 않아야 한다.
- **맥과 윈도우 비교 기준:** 변환본이 글자까지 같을 필요는 없다. 기준은 지문 비교(`check_changes`)에서 바뀐 단위 0개다. 줄바꿈 차이는 변환 직후 LF로 맞춘다(맥 결과는 그대로). 그 밖의 차이가 나오면 비교 규칙이나 지문을 고치지 말고 멈춰서 사용자에게 보고한다.

### 5.5 설치 프로그램

**담당자가 보는 순서**
1. GitHub 저장소 첫 화면 안내에서 `내규챗봇_설치.bat` 을 받는다(초대받은 뒤 로그인 필요).
2. 더블클릭한다. 윈도우 보호 경고가 뜨면 "추가 정보 → 실행"을 누른다.
3. 진행 상황이 쉬운 말로 나온다. 중간에 GitHub 로그인 창이 뜨면 본인이 로그인한다.
4. 끝나면 **준비 완료 화면**이 열린다.
5. 그 화면의 링크로 Claude 데스크톱 앱을 설치하고 본인이 로그인한다.

**프로그램이 하는 일**
- 설치 위치는 `%USERPROFILE%\내규챗봇`. OneDrive 동기화 폴더를 피한다.
- 파이썬·Node.js·Git을 PC 전체에 설치하지 않고 `도구\` 폴더에 넣는다. 관리자 권한이 필요 없고 판이 고정된다.
  - 내려받을 때 공식 배포처의 고정 판을 쓰고 **체크섬을 확인한다.** 맞지 않으면 멈춘다.
  - Git은 Claude Code가 필요로 하는 Bash까지 있는 판을 쓴다(PortableGit 예상. 만드는 사람이 Claude Code 윈도우 요구 사항을 확인한다).
  - 사용자 PATH에 `도구\` 경로를 넣는다.
- 저장소를 받는다. 이미 있으면 받은 그대로 둔다.
- `.venv` 를 만들고 고정 판 패키지를 설치한다. `npm` 으로 고정 판 kordoc, jsdom, cfb를 저장소에 설치한다.
- 원본 72개를 변환하고 `build_db` 를 돌려 `data/` 를 만든다.
- **바뀐 단위 0개, 다시 확인 문답 0장을 확인한다.** 다르면 멈추고 그 내용을 화면에 보여 준다. 지문을 저절로 다시 찍지 않는다.
- `data/snapshot_texts.json` 을 새 변환 결과로 만든다(지문은 그대로).
- 낱말 경계 확인, 양식 떼기와 검사, 화면 파일 만들기, 시험을 돌린다. 판 번호는 올리지 않는다.
- `alio_release.py refresh` 후 `install_watch.py --mode full` 로 매주 확인을 등록한다.
- `git config` 에 담당자 이름과 메일을 묻는다.

**성질**
- 다시 돌려도 안전하다. 끝난 단계는 건너뛰고, 중간에 실패하면 어디서 왜 멈췄는지 쉬운 말로 보여 주고 다시 실행하게 한다.
- 진행 기록을 `내규챗봇\설치기록.log` 에 남긴다.
- 한국어 윈도우에서 글자가 깨지지 않게 `.bat` 안에는 영문만 쓰고, 쉬운 한국어 안내는 PowerShell(UTF-8 BOM) 또는 파이썬이 보여 준다.
- 막히면 쓸 수 있도록 손으로 설치하는 안내 `docs/윈도우_설치_안내.md` 를 함께 둔다.
- 맥에서 새로 받을 때도 쓸 수 있는 같은 준비 단계를 파이썬 스크립트로 두고(`scripts/setup_project.py`), `.bat` 은 도구를 받은 뒤 그것을 부른다.

**준비 완료 화면:** 단계별 통과 여부, 내규 수, 바뀐 조문 0개, 카드 수, 판 번호, 매주 확인 등록 여부, Claude 설치 링크, 다음에 할 일.

### 5.6 AI 재확인 바꾸기

- `blind_check.py` 에서 로컬 모델 호출을 없애고 두 단계로 나눈다.
  - **문제 만들기:** 고른 문답마다 질문, 인용 조문 원문, 항목 이름을 파일로 쓴다. 문답의 답은 넣지 않는다.
  - **채점:** AI 답 파일을 읽어 지금의 비교 규칙(`compare`)으로 판정하고 `reports/blind_check.*` 를 쓴다.
- AI 쪽은 개정 반영 스킬이 Claude 하위 작업으로 돌린다. 하위 작업은 문제 파일만 읽고 답 파일만 쓴다. 카드 파일을 읽지 못하게 지시한다.
- 대상은 이번에 고치거나 새로 만든 문답만이다. 1,000장 전체 재확인은 하지 않는다.
- 답은 한 번에 나눠 맡기고 끝난 만큼 파일에 쌓아, 멈춰도 이어서 할 수 있다.
- 문제 파일과 답 파일은 어떤 AI가 답했는지와 무관한 형식으로 정하고, 답 파일에 답한 AI 이름을 적는다. 다음 과제에서 API·로컬 모델이 같은 파일을 채우게 하기 위해서다.
- 기본 모델은 Sonnet.
- **합격 기준:** 비교 규칙은 바꾸지 않는다. '판정 필요'는 지금처럼 원문과 대조해 고치거나 `reports/review_decisions.json` 에 결정을 남긴다. 만들 때 이미 고쳐진 문답 20장으로 한 번 시험해 '판정 필요' 비율을 지금 결과(`reports/blind_check.json`)와 비교해 사용자에게 보고한다. 값이 크게 달라도 임의로 기준을 조정하지 않는다.
- 하위 작업이 카드를 읽지 못하게 막는 것은 지시문에 의존한다. 이 한계를 안내서에 적는다.
- 같은 회사 모델이라는 한계를 안내서에 적는다. 내용 판단은 소관부서 검수가 맡는다. 기관 문서의 문구는 11장을 따른다.

### 5.7 Claude 사용 한도 대비

- 개정 반영 스킬에 "한도에 걸렸을 때"를 넣는다. 고친 카드는 파일에 남아 있으니 시간이 지난 뒤 "개정 반영 이어서"로 계속한다. 이어서 할 때 이미 고친 카드를 다시 고치지 않는다.
- 그동안 새 판을 만들면 영향받은 문답에 "재검수 전"이 붙는다.
- 스킬의 하위 작업은 필요한 것만 돌린다(새 내규 대량 작성 때만 나눠 맡긴다).
- 안내서에 사용 크레딧 안내를 넣는다.

### 5.8 저장소 안의 설명서와 스킬

- **`CLAUDE.md`(새 파일):** 담당자의 Claude가 읽는 프로젝트 설명서. 지금 만든 사람의 기억 파일에 있는 내용 중 담당자에게 필요한 것을 옮긴다.
  - 답은 쉬운 한국어로, 사용자는 개발자가 아님

  - 글자 검색의 함정, `dist/` 와 판 번호, 인공지능전환관리세칙 제약
  - `git add -A` 금지, kordoc 판을 임의로 올리지 않기

- **스킬 내용:** 경로를 저장소 기준으로 고치고, `python3` 를 맥·윈도우 모두 되는 표현으로 쓴다.
- **안내서:** `docs/유지보수_안내.md` 의 "이 맥 1대"를 고치고, 인계 때 담당자가 할 일 목록을 넣는다.

### 5.9 일상 흐름과 사본 보관

- 개정 반영 1단계 전에 저장소를 최신으로 받는다(`git pull`).
- 5단계 커밋 뒤 GitHub에 올린다(`git push`). 스킬이 묻고 한다. 이것이 사본 보관이다.
- 받거나 올릴 때 충돌하면 고치려 들지 말고 멈춰서 알린다.
- 두 PC에서 동시에 작업하지 않는다. 안내서에 적는다.
- 판 파일(`dist/`)은 저장소에 넣지 않는다. 3번 과제에서 다룬다.

### 5.10 GitHub Actions 시험

`.github/workflows/windows.yml`. `windows-latest`(x64). main에 올릴 때와 손으로 실행할 때 돈다.

- 저장소를 받은 곳에서 준비 스크립트를 돌린다. 로그인과 사람 입력이 필요한 단계는 시험 모드로 건너뛴다.
- 도구 내려받기와 체크섬 확인도 실제로 돈다.
- `test_watch_alio.py`, `test_forms.py`, `test_engine.js`, `ui_test.js`, `check_knowledge.py` 를 돌린다.
- 변환 결과가 맥과 같은지 본다: 바뀐 단위 0개, 다시 확인 문답 0장.
- 원본 하나를 일부러 고친 시험 자료로 원문 비교가 돌아 바뀐 조문이 잡히는지 본다.
- `install_watch.py` 가 만든 작업을 `schtasks` 로 실제 등록하고 조회한 뒤 지운다.
- 설치를 두 번 돌려 두 번째가 안전한지 본다.
- ALIO 접속은 시도하되, 해외 서버라 막히면 실패로 치지 않고 알림으로 남긴다. 나머지는 가짜 응답 시험이 맡는다.
- 윈도우 무료 분 수가 정해져 있으니 다른 때는 돌지 않는다.

## 6. 다 됐다고 볼 기준

1. GitHub Actions의 윈도우에서 설치 스크립트가 처음부터 끝까지 돌고 두 번째 실행도 통과한다.
2. 그 윈도우에서 다시 변환한 결과가 바뀐 단위 0개, 다시 확인 문답 0장이다.
3. 화면 파일이 만들어지고 위 시험이 모두 통과한다.
4. 이 맥에서 같은 시험이 모두 통과하고, `update_rules.py status` 가 "바뀐 파일이 없습니다"이며, 화면 파일의 카드 수가 옮기기 전과 같다.
5. 새로 받은 빈 폴더에서 맥으로도 준비 스크립트가 끝까지 돈다.
6. GitHub 저장소에 `[개정근거]`, `contacts` 파일이 없다.
7. 비개발자 기준 문서: 설치 안내, 인계 할 일 목록.
